# TRAE宝表情工厂 · 说明-README

> 交互式定制表情生成网站原型。基于活动《TRAE宝表情包小赛》的角色三特征与自绘参考图开发，
> 支持为 TRAE宝 创建自定义表情与动作，实时预览并导出 1:1 表情图。

## 一、快速运行（三选一）

| 方式 | 操作 | 说明 |
|---|---|---|
| 直接打开 | 双击 `index.html` | 素材已 base64 内嵌，离线可用（推荐） |
| 启动脚本 | 双击 `启动网站-start.bat` | 自动起本地服务并打开浏览器 |
| 命令行 | `python -m http.server 8923` 后访问 `http://127.0.0.1:8923/` | 需在文件夹内执行 |

无任何外部依赖、无构建步骤、无网络请求；所有图片仅在浏览器本地处理，不上传数据。

## 二、功能清单

- **姿势**：全部 10 款均为手绘 3D 模型实时绘制（站立/打招呼/庆祝/摊手/叉腰/奔跑/跳跃/敲键盘/比心/骑马），
  底部参考图均为自绘图稿，可单张保存，**不进入生成链路**。
- **骨骼（3D）**：手绘模型 = MC 式单段长方体建模（头/躯干/双臂×2/双腿×2/手/脚），
  层级骨骼 + 13 个关节滑杆（身体转/倾/侧倾、头转/点头、肩侧摆/前后摆、髋侧摆/前后摆），
  预览画布可直接**按住拖动转身**——左右拖动支持连续 **360°**（越过 180° 自动归一，不中断手感），
  上下拖动只做轻微前倾 / 后仰且方向与鼠标一致、±25° 内不会翻倒；
  还可以**拖动手 / 脚 / 头**——IK 反解关节角度并实时回填滑杆，
  滑杆与拖拽任意混用；表情贴在 3D 屏幕上随头部旋转（透视纹理映射）。
- **部位（v1.7.0）**：8 类 / 13 个可选实例（头/颈/躯干 + 左右上臂/前臂/手/腿/脚），
  可从部位页按钮或画布单击选中并高亮；每个部位独立调整整体尺寸（0.50~1.60×）、局部 XYZ 旋转（±180°）
  与局部 XYZ 位移（±120），父级带动子级；支持当前部位 / 全部位复位。单击与拖动按 5px 阈值分流，
  原 IK / 转身保持可用；切换姿势保留参数，高亮不进入 PNG / GIF 导出。
- **体型（v1.8.0）**：全身塑形（捏脸式）——头宽 / 头高 / 头深、屏幕占比、躯干宽 / 长、四肢粗细、
  手臂长度、腿长度、脚掌长度 10 项比例滑杆；**官方标准体型为默认档**，另有 Q版大头 / 高挑细身 /
  壮实魁梧 / 迷你袖珍 / 大屏旗舰 / 长腿仔 / 方块厚实 7 款预设与「🎲 随机体型」（0.78~1.28 内抽取）。
  肩 / 髋 / 颈关节位置随躯干与头自动联动；超高体型自动缩小取景，全身始终入画；
  边框 / 玻璃 / 缺角等结构特征件不随体型缩放。当前体型可**命名保存**（最多 12 套，点击应用 / ✕ 删除）、
  **导出 JSON** 分享与**导入**（比例按滑杆范围钳制，非法文件仅提示不崩溃）；
  体型存 localStorage（`traeEmoji.body.v1` / `traeEmoji.bodySaved.v1`），刷新恢复，
  PNG / GIF / 批量导出与姿势缩略图均使用当前体型；「重置」一并还原官方标准体型。
- **表情**：24 款像素 LED 屏幕表情（平常心/开心/大笑/生气/暴怒/大哭/委屈/爱心眼/星星眼/晕/困/
  无语/疑问/墨镜/脸红/流汗/坏笑/惊讶/眨眼/吐舌/燃烧/思考/慌张/加载中），风格对齐官方「黑色屏 + 发光像素眼」。
  各姿势的屏幕脸会被自动覆盖重绘，任意表情 × 任意姿势自由组合。
- **二次创作内置表情（v1.9.0）**：每张表情卡片右上角都有 ✎ 角标，内置表情点开即**以真实像素为底稿**进入画板，
  可改名（≤8 字）、改发光色、改眼睛亮度、改像素；保存为覆盖记录（保持原 id，存 `traeEmoji.faceEdit.v1`），
  未改动的内置表情仍走官方原画；改过的表情角标转金色常亮，编辑器内「↺ 还原官方表情」一键复位。
- **自定义表情（像素画板）**：表情页末尾「自己画」打开 40×28 像素画板——画笔/橡皮/填充/**吸管**、1~3px 笔刷、
  左右对称、撤销（Ctrl+Z）/清空/套用「平常心」底稿、**20 色调色板 + 🎨 自定义取色 + 🖥 屏幕取色** + 发光色 +
  **眼睛亮度 40%~160%** + 实时预览（当前色以「色点 + HEX」显示，吸管单击已有像素即取色并自动切回画笔）；
  保存后与内置表情并列参与随机/套系，写入 localStorage（最多 24 个），图标右上角 ✎ 可再编辑或删除。
- **配色（v1.5.0）**：8 款预设（官方炭灰/纯白/米白/薄荷/樱花粉/天青蓝/柠檬黄/暮紫）+ 全局色板 +
  头部/躯干/手臂/腿部/屏幕边框 5 个部位独立取色；只换外壳材质，屏幕玻璃与像素表情不变，
  手/脚/缺口阴影按官方关系从基色派生，光照随基色自动换算明暗；「↺ 还原官方配色」一键复位，
  配色存 localStorage（`traeEmoji.skin.v1`），刷新仍可用。
- **背景**：透明 / 纯色 4 款 / 渐变 3 款 / 图案 4 款（科技网格、放射线、波点、星空）；
  另支持**上传本地图片作背景**——填充 / 适应 / 平铺三种铺放方式 + 水平/垂直位置微调，
  图片归一化到最长边 1024 后存本机 localStorage（`traeEmoji.customBg.v1`），刷新仍可用。
- **文字**：自定义文案 + 14 个高频预设；位置（上/下/无）× 样式（白字黑边/荧光发光/气泡框）
  × 颜色 × 大小，自动缩放防溢出。
- **贴纸（自由摆放）**：8 款内置贴纸（汗滴/怒气/Zzz/星光/爱心/音符/灯泡/问号）点一次加一张，
  可在预览画布直接拖动，滑杆调位置 / 大小（0.25~3×）/ 旋转（±180°），按钮排层级（上移/下移/置顶/置底），
  可删除单张或清空全部；另有**上传图片贴纸**与 **32×32 像素画板**（画笔/橡皮/填充/吸管、1~3px、左右对称、
  撤销、20 色板 + 自定义取色 / 屏幕取色）。贴纸与位置/大小/旋转写入 localStorage（`traeEmoji.stickers.v1`），刷新仍可用。
- **指定部位贴纸**（v1.10.0）：选中贴纸后在「挂载部位」下拉选择 13 个部位（头/颈/躯干/左右上臂/前臂/手/腿/脚）
  之一，贴纸即钉在该部位上——换姿势、拖手柄、播放循环动画、捏部位尺寸时贴纸随部位矩阵
  **移动 / 旋转 / 缩放**；挂载后用「水平 / 垂直偏移」滑杆（±260）或直接拖动微调相对位置；
  同一部位同时只挂一张（新挂载自动替换旧贴纸），切回「自由摆放」即卸下且贴纸原地保留；
  列表对挂载贴纸加 📌 标记，挂载信息一并存 localStorage，三类贴纸（内置/上传/手绘）通用。
- **一键套系**：按官方提示词示例场景（爱你哟/收到/加油鸭/让我想想/我看好你哟/不愧是你/摸鱼中/崩溃中）
  预配全套参数。
- **随机灵感**：一键随机组合，用于快速探索。
- **循环动画**（v1.4.0）：呼吸起伏、左右摇摆（绕身体中轴原地转身、中心点不动）、
  四肢走路式交叉摆动（左臂↔右腿同相）、眨眼/表情闪现（周期末 10% 短促闪现第二表情）、
  循环周期 0.8~3.2s；**默认暂停**（v1.9.0 起），点「▶ 播放预览」才开始，设置存 localStorage（`traeEmoji.anim.v1`）；
  旧存档通过一次性迁移标记（`traeEmoji.animAutoOff.v1`）强制暂停一次，之后手动播放的选择正常记忆。
- **关键帧动画（v1.11.0，「动作」页）**：把「骨骼」页摆好的姿势（14 项角度全量快照）串成连续动作——
  帧间 smoothstep 插值平滑过渡；▶ 循环播放 / ⏸ 暂停停在此刻 / 拖播放头预览任意时刻 / ⏹ 回到骨骼退出查看，
  全程不写入当前骨骼，所见即所得；每帧可改时刻（0~30s）、看姿势缩略图、「⇥ 载入到骨骼」微调后「⟳ 更新」、删除。
  **7 款动作预设**（招手/点头/摇头/开心跳/左右看/扭腰摇摆/举手欢呼，首尾闭合循环顺滑，载入自动切站立）；
  **多段串联**：任意预设或「我的动作」⤵ 追加到时间轴末尾（衔接留 0.4s 平滑过渡），追加后直接播放；
  **我的动作库**：命名保存 12 套（同名覆盖）/ 载入 / 删除，串联下拉同步刷新，JSON 导出分享与导入；
  与循环动画互斥（播放一方自动暂停另一方），切离「动作」页或拖动身体 / 肢体自动退出时间轴查看；
  时间轴与库存 localStorage（`traeEmoji.kf.v1` / `traeEmoji.kfSaved.v1`），「重置」清空时间轴但保留动作库。
- **导出**：PNG 1:1（1024/720/480），下载单张 / 复制到剪贴板 / 一键导出 8 张套系；
  **GIF 动图**（🎬 零依赖自研编码器，透明底不叠影，建议 480 档；**v1.11.0 起有关键帧时按时间轴
  12fps 采样（8~48 帧）优先导出关键帧动画**，否则保持 16 帧循环动画导出）；
  **APNG 动图**（🖼 零依赖自研编码器，无限循环、全彩无损——像素表情的 LED 点阵不被 256 色量化，
  透明底不叠影，按时间轴 12fps 采样，建议 480 档）。
  透明背景导出直接符合活动投稿建议（透明底 PNG、1:1、文案简短）；PNG 始终是静态姿势。

## 四、技术要点（复用价值）

1. **像素表情系统**：40×28 网格画布 + 一组像素原语（菱形眼/弧线/爱心/星形/螺旋/汗滴…），
   `imageSmoothingEnabled=false` 放大保持硬边，`shadowBlur` 双通道叠加做 LED 辉光。
   注意：canvas 阴影不受 CTM 缩放影响，缩略图需按设备像素比例传入 `glowScale`。
   **自定义表情 = 纯数据**：`{ id, label, glow, bright, cells[40×28] }`（空串=透明），
   `customDef()` 把 cells 包成和内置表情同构的 `draw(p)`，因此缓存/缩略图/3D 贴图/导出全链路复用同一套代码；
   增删改后调用 `rebuildFaces()`（就地重建 `FACES`，保证外部引用不失效）并 `delete faceCache[id]`。
   **内置表情二次创作 = 覆盖记录**（v1.9.0）：`FACE_EDITS[内置 id] = { label, glow, bright, cells }` 存
   `traeEmoji.faceEdit.v1`，`rebuildFaces()` 命中覆盖时用 `editedFaceDef()` 生成与自定义表情同构的 def（保持原 id，
   随机/套系/第二表情全部即时生效）；编辑器以 `faceCellsOf(id)` 栅格化官方像素为底稿，已有 `cells` 时直接读存档，
   避免把已烘焙的亮度再乘一次；`delete FACE_EDITS[id]` + `rebuildFaces()` 即还原官方。
   **眼睛亮度**（`clampBright` / `faceBright` / `brightenCanvas` / `brightHex`）：0.4~1.6 系数，像素在
   `getFaceCanvas` 缓存位图里逐通道乘系数（1 时不进 getImageData，官方外观零开销、像素级不变），
   辉光色 `faceGlow()` 按同一系数换算，3D 贴图 / 缩略图 / PNG / GIF / 编辑器预览全部一致。
   **取色（v1.9.1）**：`GRID_PALETTE` 20 色由表情 / 贴纸两个画板共用；`gridPickCell(E,x,y)` 做画板吸管
   （取到即回填 `E.color` 并切回画笔），`screenPickColor(cb)` 包 `EyeDropper.open()`、不支持时 toast 降级；
   `type=color` 隐藏输入只负责调起系统调色板，取色后统一走 `feApplyColor` / `seApplyColor`
   （校验 HEX → 同步色板高亮、色点与 HEX 文本；黑色不进入发光色下拉）。
2. **3D 骨骼引擎**（`renderProcedural`）：世界坐标 y 向下、透视相机在 +z；部位 = 长方体
   （比例两轮校准：官方全景图四视角 + `../02-角色五视图-turnaround/` 正/侧/背/顶，
   按「头宽归一、头顶点对齐」逐视角叠影比对。终值 头 370×316×336（宽:高:深 = 1:0.854:0.908，按反馈收窄、缩短后脑），
   躯干 175×162×152，臂截面 58、单段臂长 140（与五视图「手到腰线」一致），
   腿 82 宽×116 深、单段腿长 102，脚 72 宽×142 深带缝隙；屏幕占头宽 0.74、占头高 0.684、上缘下移 53）；
   **原骨骼按 MC 式简化**：躯干→头/双臂/双腿，肩 / 髋驱动肢段整体摆动；v1.7 新增颈部连接节点与
   左右前臂节点，肘部弯曲由部位附加变换驱动（默认不启用，仍保持单段外观），腿部支持前后摆 + 侧摆，
   **头部是整块长方体 + 左下角缺角**（宽 0.11W / 高 0.12H / 深 0.17D，由 3 块盒子拼成 L 形；
   缺角整体落在「脸面边框」内，与屏幕板左边 / 下沿各留 3~4 空隙，凸出的屏幕板不会压住缺角；
   缺口后壁贴一层阴影片（v1.6.0：铺满缺口开口、按头色 ×.86 压暗，原先内缩 2 的亮边在斜视角会把凹槽读成外凸板）；
   拼块用 `edge:'self'` 描边消除内部接缝线，整体仍读作一块）；
   上举姿势（打招呼/庆祝/比心）统一 120°，确保手臂在头部外侧不穿模；
   每帧算世界矩阵 → 6 面背剔 + 朗伯光照（画家算法排序）→ 屏幕作为特殊面用双三角形透视纹理映射贴表情，随头部旋转。
   **画家算法排序键 = 该面四角的「最近点 z」**（v1.6.0 由面中心 z 改）：按中心排序时大面（头侧壁，中心 z≈0）
   会整体压住贴近它的近侧面（抬手手臂 z≈44），出现「手臂穿头 / 远侧面盖住近侧面」的假透明。
   骑马 / 桌面等道具面用同一口径，否则会和肢段比错量纲（马身反而被腿面吞掉）。
   **屏幕是凸出式装配件**（v1.6.2 起为「有纵深的边框框条 + 内缩的深色玻璃实体」）：边框为四条真正有厚度的框条
   （纵深 26 = `bezelDepth`，v1.7.1 由 20 加深、内部嵌入头部 14，前表面仍停在凸出端 12），玻璃外廓再内缩 3（`glassInset`）、纵深 34 的深色实体
   且前表面再内凹 4，正/侧/顶视都有可见台阶（五视图与官方一致）；侧视角由框条侧壁形成「浅色边框包着深色屏体」的
   实体断面，90° 前后边框仍成条可见。屏幕面的可见性用**屏幕空间投影有向面积**判定
   （正 = 正面朝向，留 2px² 死区），排序锚 `max(屏幕四角 z, headFrontZ) + bezelProtrude + 4`。
   光照拟合全景图实测（左侧面 55 / 顶 52 / 背 51 / 正面 48）：高环境光 LUM_A=0.873 + 弱方向光
   LUM_D=0.151，光向左上后方 `[-0.84,-0.477,-0.356]`；相机长焦弱透视 D=3200、俯角 0.055rad
   （参考图头底缘平直、顶面微露）。默认配色为官方中性暖炭灰（头 #373834/躯干 #2d2e2b/手臂 #3a3b37/腿 #2f302d，
   v1.5.0 起可由用户整体或按部位替换；v1.12.0 起手臂略亮于躯干，垂手站立也能读出独立手臂轮廓），
   地面为方向性接触阴影（偏向右侧）+ 淡倒影；背景新增「影棚」复刻官方全景环境。
   踩坑记录：骨骼角度统一用「度」，进矩阵前转弧度（曾因 7° 被当 7 弧度导致模型翻滚）；
   y 向下坐标系里肢体延伸方向是 +y，链式关节别按 y-up 直觉写负号；相机在 +z 时画家算法
   按 z 升序绘制、屏幕面深度加正偏移；GEO3D 中头/躯干为全尺寸（用时折半），
   臂/腿/脚字段为半尺寸直用——两种约定并存，改参数前先核对；
   轮廓测量务必按 alpha>200 取实体像素，地面阴影会把包围盒拉长 8~10%。
   v1.6.0 显示修复踩坑：①「肩 / 髋关节填充」盒体上端探出肢段轮廓，转身即整块外露（已删除，
   根缝由头部体积遮住，删除后全姿势封闭空洞检测为 0）；②排序键必须取「面最近点」，
   且角色面 / 道具面 / 屏幕锚定三处同口径，只改一处会引入新的错序（曾出现马身被腿面吞掉）。
   v1.6.1 屏幕踩坑：①「法线 × 视线点积」判可见性偏严——头心在 y≈-233、相机又有 3.15° 俯角，
   法线还剩一点朝相机也被判背面（`headPitch=25°` + 总转角 90° 时 z 分量 -0.046 即被剔除），
   屏幕整块消失露出机身色；改用投影有向面积后转角过程连续收窄。
   ②大四边形（头正面）的「最近点 z」会吞掉贴在其上的凸出装配件（45° 时头正面 zNear≈249 vs 装配件≈227），
   需给装配件盒体打 `front` 台阶、排序键取 `max(zNear, headFrontZ + front)`（边框 1 / 玻璃 0.6，
   台阶差保留边框压玻璃的真实前后关系），否则斜视角看不到边框与玻璃。
   ③平面在正侧 90° 必然投影为线（面积 0），别指望靠加厚玻璃解决，靠的是「让玻璃成为深色实体」——
   此时读作头侧一枚深色屏幕侧板，不会与机身同色消失。
   v1.6.2 边框踩坑：④**边框本身也是平面**——v1.6.1 的一圈 8 深薄板转到 90° 同样投影为线，
   整圈边框凭空消失；给边框真实纵深（`bezelDepth 20 → 26`，比玻璃更靠外）后靠侧壁成条可见。
   ⑤边框与玻璃**共面**时排序键会相等，稳定排序让后插入的玻璃前脸盖掉整圈边框；
   现在玻璃外廓内缩 `glassInset 3` 并把 `front` 台阶差拉开（边框 1 / 玻璃 0.6）才稳定。
   ⑥`front` 钳制必须作用于**全部 6 面**：只钳外向前面会让侧壁被头前脸吞掉
   （实测 45° 边框像素 11390 → 5251、玻璃 7875 → 1211），侧壁正是「任何角度可见」的来源。
   v1.7.1 侧视 / 抬手踩坑：⑦背面剔除的法线**必须先归一化**——部位整体缩放会等比拉长 `rotOnly` 的法线，
   `dot` 随之放大，放大后的薄片（手 / 脚 / 边框）被 0.001 阈值误判成背面而整块消失；
   归一化后再叠「投影有向面积 < 2px²」兜底，临界薄面改由面积判断，收窄过程连续。
   ⑧相邻面在斜视角会留下亚像素拼合缝（看起来像一条黑缝），填充后先按面色外扩约 0.75px 描边再叠转折描边即可填平；
   肘 / 脚这类可旋转的肢端，实体盒要向父级内部延伸 8（静止时不绘制或藏于父级体积内），否则单独旋转必出楔形缺口。
3. **场景道具**（`buildProps` / `collectProps`）：敲键盘姿势附加「桌子+笔记本」、骑马姿势附加「马」，
   道具与角色 boxes 同构，但以**恒等矩阵（世界坐标系）**渲染，不随角色骨骼转动；
   与角色面一起进入画家算法排序，保证遮挡关系正确。
4. **导出**：离屏 canvas 按目标尺寸整体重绘（非缩放截图），`toBlob` 下载 / `ClipboardItem` 复制。
5. **自定义背景**（`drawCustomBg`）：上传图先等比归一化到最长边 1024 再进渲染，避免超大图拖慢预览；
   填充 / 适应用等比缩放（`max` / `min` 取 `s/w, s/h`），平铺用 `createPattern` 并整体 `scale(s/BASE)`，
   保证 1024 / 720 / 480 三档导出的构图与预览一致；偏移统一用「画布百分比」，与尺寸无关。
   持久化按透明像素自动选 PNG / JPEG，`localStorage` 写入失败时降级为会话内可用并提示。
6. **自由贴纸**（`drawStickerCore` / `drawStickerItem` / `hitSticker`）：
   贴纸实例 `{ uid, t:'b'|'img', ref, src, x, y, scale, rot, mount }`，数组顺序即层级；x/y 用画布百分比、
   尺寸统一用 `unit = s / 1024`，所以预览与三档导出构图一致。内建贴纸是**矢量绘制**（像素原语 + `shadowBlur` 辉光，
   阴影不受 CTM 影响需按 `scale * unit` 手动缩放）；图片/手绘贴纸按最长边 240 等比绘制，手绘图 `pixel:true`
   关闭平滑保持像素风。选中框只在 `render(ctx, s, ui)` 的 `ui=true`（预览）时绘制，导出不含；
   命中检测把点击点**反向旋转**到贴纸本地坐标后再按包围盒判断，旋转后依然好点。
   手绘贴纸存 32×32 PNG dataURL（体积小），上传图归一化到最长边 512 并按透明通道选 PNG / JPEG。
   表情画板与贴纸画板共用网格工具（`gridBlank` / `gridStamp` / `gridLine` / `gridFlood` / `gridRender`）。
   **挂载式贴纸（v1.10.0）**：实例带 `mount: { part, dx, dy }` 即钉在部位上；渲染管线把当帧骨骼存入
   `LAST_SK`，`stickerXform()` 统一算平移（部位锚点世界矩阵投影 + 偏移）/ 旋转（肢体方向投影偏角，
   相对竖直向下为 0°）/ 缩放（部位附加 scale），绘制 / 选中框 / 命中全走同一变换；
   动画与 GIF 逐帧渲染时 `LAST_SK` 同帧更新，挂载贴纸即所见即所得。挂载与自由式同层渲染、
   同一 localStorage 记录（无 mount 字段 = 自由式，旧存档天然兼容）。
7. **肢体拖拽 IK**（`posedSkeleton` / `updateSkeletonMatrices` / `ikSolve` / `hitLimb` / `drawIkOverlay`）：
   手 / 脚手柄 = 关节链端点的屏幕投影；IK 与实际渲染共用 `buildSkeleton + updateSkeletonMatrices`，
   肩 / 髋原骨骼与 v1.7 部位附加变换都走同一矩阵，保证解出的角度与渲染视觉一致。
   反解在屏幕空间做数值搜索：11×11 粗网格 + 7 轮 3×3 局部细化（步长 ×0.45 收缩），
   代价 = 屏幕距离² + 0.02 × 角度偏移²（锚定项：以当前角度优先，抓取瞬间不跳角；
   目标不可达时手柄停在最近可达点）。解出的两角度直接写回 `S.rig`，与 13 个滑杆共用同一状态，
   因此滑杆与拖拽天然同步。头部手柄不做位置反解，改为朝向增量（headYaw / headPitch）。
   手柄命中按投影点距离判圆（手 r=40 / 脚 r=44 / 头 r=64，手脚优先于头），
   高亮圆环只画在预览层（`render(ctx, s, ui)` 的 ui 开关），导出不含。
   踩坑记录：自动化验证合成 PointerEvent 时，位移是 CSS 像素而 IK 目标在 1024 基准画布坐标，
   必须按 `rect.width / 1024` 折算，否则会误判「IK 解不准」（首测 110px 假偏差即由此而来）；
   悬停高亮要在 pointermove 里做「命中目标变化才重绘」，否则鼠标掠过画布会高频全量重绘。
8. **指定部位调整**（`S.parts` / `PART_DEFS` / `updateSkeletonMatrices`，v1.7.0）：
   13 个实例各存 `{ scale, rx, ry, rz, x, y, z }`，在原骨骼矩阵之后叠加局部 `T × R × S`；
   根躯干→颈→头、上臂→前臂→手的父子链使父级自然带动子级，左右侧分别保存、互不影响。
   主预览把带 `part` 标记的投影面缓存为 `PART_FACE_CACHE`，按画家算法反向命中；单击 / 拖动以 5px 分流，
   高亮由 `drawPartOverlay` 在 `ui=true` 时追加，离屏 PNG / GIF 不绘制也不覆盖命中缓存。
   **默认外观保护**：颈部仅有不绘制的连接代理；前臂处于默认状态时，仍绘制 v1.6.2 的原始整臂网格，
   上臂 / 前臂用代理盒分别命中与高亮，只有前臂参数离开默认值才切换成分段实体。这样不会引入静态中缝、
   相接端盖或轮廓变化；10 个姿势的 1024² 非透明像素已与 v1.6.2 逐项核对一致。
   调试入口新增 `__traeEmoji.parts`（defs / select / hit / reset），矩阵调试新增 `updateSkeletonMatrices / mS`。
9. **外壳配色**（`skinMix` / `skinFromBase` / `buildSkinUI` / `shadeHex`，v1.5.0）：
   状态 `S.skin = { head, torso, arm, leg, bezel }`，`buildSkeleton` 每帧直接读取，因此预览 / 姿势缩略图 /
   批量导出 / GIF 共用同一份配色。全局色板取一个基色，乘以官方明度比例派生全身
   （躯干 .82 / 手臂 1.04 / 腿 .86 / 边框 .92；v1.12.0 手臂由 .80 提到 1.04，避免与躯干同色不可见），
   手 / 脚再按官方「比本肢略亮」提亮（×1.16 / ×1.19），
   头部缺角阴影片按头色压暗（×.78）——**手 / 脚 / 阴影始终由基色派生，换色不会出现「部件不同色系」**。
   光照自适应：`shadeHex` 在基色峰值 × 亮度系数 > 255 时把系数压到 `255 / 峰值`，
   避免浅色最亮面逐通道削顶（削顶会丢失正 / 侧 / 顶层次）；深色与道具颜色不受影响。
   屏幕玻璃（coverColor `#161b18`）与像素表情固定深色，不参与换色，保证 LED 可读性。
   姿势缩略图按 160ms 防抖重建（`refreshPoseThumbs`），拖动原生取色器时不逐帧重算 10 张缩略图；
   配色存 localStorage（`traeEmoji.skin.v1`），缺失 / 损坏时回落到官方配色。
10. **全身塑形引擎**（`BODY_BASE` / `BODY_REST` / `applyBody` / `fitCamera` / `buildBodyUI`，v1.8.0）：
   原硬编码 `GEO3D` 拆为「官方实测基准 `BODY_BASE`（v1.7.4 定稿）× 十项比例 `S.body`」，
   `applyBody()` 派生写入 `GEO3D`，骨骼 / 渲染 / IK / 缩略图全链路只读 `GEO3D`——体型改一处全局生效，
   `window.__traeEmoji.dbg3d.GEO3D` 引用同一对象。
   **官方像素不变的构造性保证**：直接量 = 基准 × 比例（IEEE ×1 精确不变）、联动量用「基准 + Δ」形式
   （肩X = 基准 + Δ躯干半宽 + Δ臂半宽、髋X = 基准 + Δ躯干宽×0.24、颈咬合 5.5 等），
   比例全为 1 时逐字段严格等于旧字面量；`fitCamera` 首次调用只记录官方构图的头顶 / 脚底投影锚点，
   官方档 `CAM={zoom:1.36, cy:660}` 一步不动。
   **取景自适应**：超高体型把全身投影高度等比压回官方构图高度（缩 `zoom`），再把头顶锚定到官方头顶
   （`CAM.cy = 660 + 官方头顶 - 当前头顶`）；官方 / 矮小体型不缩放不位移。
   **屏幕占比硬约束**：`screenW ≤ headW - notchW - 32`（左缘给缺角留缝）、
   `screenH ≤ headH - 2×notchH - 22`（下缘不越缺角顶），占比过大自动收口而不穿模。
   踩坑记录：①派生公式禁止在官方档引入非精确常数（如 `175×0.24` 的 0.24 非二进制精确值，
   会产生 42.00000000000001 一类的误差，破坏像素级一致性），一律改「基准值 + 变化量×系数」形式，
   官方档 Δ=0 严格回到原值；②比例必须钳制在滑杆范围内（导入 JSON / 旧存档同口径 `bodySanitize`），
   否则极端组合会穿出缺角或把关节推出躯干；③体型变化要 160ms 防抖重建 10 张姿势缩略图
   （与配色同策略），拖滑杆时不逐帧重算；④缩略图 / GIF / 批量导出都读同一 `GEO3D`，
   改体型后无需逐处同步——但 localStorage 的体型键要在 `loadBody`（早于 `buildOptions`）恢复，
   否则缩略图先用官方体型构建、再被防抖刷新覆盖一遍。
11. **关键帧动画与 APNG 编码器**（`KF` / `kfRigAt` / `renderKfView` / `startKfLoop` / `TraeApng`，v1.11.0）：
   关键帧 = `{ t, rig }`（`rigClone` 全量快照，14 项骨骼角度），`kfRigAt(tt)` 在相邻帧之间逐字段
   `lerp × smoothstep`（`u²(3−2u)`，帧间平滑加减速），首帧前 / 末帧后保持端帧姿势（越界安全）；
   循环时长 = 末帧 − 首帧，播放 = `startKfLoop` 持续推进 `viewT`，采样渲染统一走
   `renderKfView(ctx, s, ui, tt)`——背景 / 角色骨骼 / 贴纸 / 文字与静态渲染同一链路，
   `renderProcedural` 内 `LAST_SK` 同帧更新，挂载贴纸随关键帧动画逐帧联动、导出即所见即所得。
   **不写入 `S.rig`**：`viewT=null` 表示不在时间轴查看（预览 = 当前骨骼静态），播放 / 暂停 / scrub
   都只改 `viewT`；`repaint` 渲染优先级 = 关键帧播放 > 播放头停留 > 循环动画 > 静态，
   两套动画互斥（`kfPauseLoopAnim` / `kfExitView`），且切离「动作」页、拖动身体 / 肢体
   （stage pointerdown 的 limb/body 分支）都触发 `kfExitView`——保证任何骨骼编辑入口即时可见，
   避免「调滑杆没反应」（预览停在插值姿势）的困惑。多段串联 = 动作关键帧整体平移接末尾
   （`base = 末帧 t + 0.4s` 缓冲，避免与末帧时刻重合导致姿势突变）。GIF / APNG 导出共用
   `kfSamplePlan`（12fps，8~48 帧钳制，delay 取整到 10ms）；APNG 编码器逐帧 `canvas.toBlob`
   提取 IDAT 后重封装为 `sig + IHDR + acTL + [fcTL + IDAT(首帧)/fdAT(后续)]×n + IEND`，
   `dispose=NONE / blend=SOURCE` 整幅覆盖（透明底不叠影），`acTL num_plays=0` 无限循环。
   踩坑记录：①PNG 规范要求 **IHDR 必须紧跟签名作为第一个 chunk**，acTL 只需在首个 IDAT 之前
   ——把 acTL 放在 IHDR 前会产出「有 acTL 标记但任何解码器都拒收」的坏文件（结构标志全对、
   Image 解码失败），务必用「解码验证」而不只是「字节标志存在」做回归断言；②新增模块的
   init 调用与函数定义命名必须逐字核对（`kfLoad` vs `loadKf` 命名不一致会让 init 在 buildKfUI
   之前 ReferenceError 中断，画布全空白且后续所有 UI 未构建）；③动作库增删后要同步刷新串联下拉
   （`rebuildKfAppendSel`），否则下拉残留已删除的选项。调试入口 `__traeEmoji.kf`
   （presets / frames / rigAt / load / append / dur / saved / state）。
